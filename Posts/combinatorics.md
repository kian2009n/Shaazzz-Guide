در بسیاری از سوالات شمارشی نیاز داریم بدانیم به چند روش می‌توان $r$ عضو را از بین $n$ عضو انتخاب کرد (بدون توجه به ترتیب). به این مقدار ترکیب یا انتخاب $r$ از $n$ می‌گوییم و آن را با $\binom{n}{r}$ نشان می‌دهیم:

$$\binom{n}{r} = \frac{n!}{r!\,(n-r)!}$$

در این بخش چند روش مختلف برای محاسبه‌ی این مقدار را بررسی می‌کنیم که هر کدام در شرایط متفاوتی به کار می‌آیند.

### مسئله

دو عدد $n$ و $r$ داده شده‌اند. می‌خواهیم $\binom{n}{r}$ را حساب کنیم.

### راه حل ساده

اولین ایده این است که $n!$، $r!$ و $(n-r)!$ را جداگانه حساب کنیم و فرمول بالا را مستقیم به کار ببریم.

!!! warning ""
    فاکتوریل خیلی سریع رشد می‌کند؛ مثلا $21!$ دیگر در `#!cpp long long` جا نمی‌شود و با سرریز (overflow) روبه‌رو می‌شویم. پس این روش حتی برای $n$های نسبتا کوچک هم جواب نمی‌دهد، در حالی که خود $\binom{n}{r}$ ممکن است عدد کوچکی باشد.

### محاسبه با تقسیم تدریجی

برای این که اعداد میانی بزرگ نشوند، می‌توانیم ضرب و تقسیم را به صورت مرحله‌ای انجام دهیم:

$$\binom{n}{r} = \frac{n}{1} \times \frac{n-1}{2} \times \frac{n-2}{3} \times \dots \times \frac{n-r+1}{r}$$

```cpp linenums="1"

long long nCr(int n, int r) {
    if (r > n) return 0;
    if (r > n - r) r = n - r; // (1)!
    long long res = 1;
    for (int i = 1; i <= r; i++) {
        res = res * (n - r + i) / i; // (2)!
    }
    return res;
}
```

1. چون $\binom{n}{r} = \binom{n}{n-r}$ است، همیشه مقدار کوچک‌تر را انتخاب می‌کنیم تا حلقه کوتاه‌تر شود.

2. بعد از مرحله‌ی $i$ام، مقدار `#!cpp res` دقیقا برابر $\binom{n-r+i}{i}$ است و در نتیجه همیشه عددی صحیح است؛ پس تقسیم بر $i$ باقی‌مانده ندارد.

این روش از $O(r)$ زمان می‌برد.

!!! warning ""
    در هر مرحله اول ضرب `#!cpp res * (n - r + i)` انجام می‌شود و بعد تقسیم؛ این حاصل ضرب میانی می‌تواند سرریز کند، حتی وقتی خود $\binom{n}{r}$ در `#!cpp long long` جا می‌شود. مثلا $\binom{62}{31} \approx 4.6 \times 10^{17}$ جا می‌شود، ولی این کد برای آن جواب اشتباه (منفی) می‌دهد. پس این روش فقط تا وقتی امن است که $\binom{n}{r} \times n$ هم در `#!cpp long long` جا شود.

### رابطه‌ی پاسکال

روش دیگر استفاده از رابطه‌ی پاسکال است:

$$\binom{n}{r} = \binom{n-1}{r-1} + \binom{n-1}{r}$$

با حالت‌های پایه‌ی $\binom{n}{0} = \binom{n}{n} = 1$. ایده این است که جدولی مانند `#!cpp dp[n][r]` بسازیم و مقادیر را از $n$های کوچک به بزرگ پر کنیم؛ هر خانه از دو خانه‌ی سطر قبلی به دست می‌آید.

??? success "اثبات"
    عضو $n$ام را در نظر بگیرید. هر انتخاب $r$تایی یا شامل این عضو است (و باید $r-1$ عضو دیگر را از $n-1$ عضو باقی‌مانده انتخاب کنیم) یا شامل آن نیست (و باید هر $r$ عضو را از $n-1$ عضو باقی‌مانده انتخاب کنیم). این دو دسته هم‌پوشانی ندارند و همه‌ی حالت‌ها را می‌پوشانند.

```cpp linenums="1"

long long nCr(int n, int r) {
    if (r > n || r < 0) return 0;

    vector<vector<long long>> dp(n + 1, vector<long long>(n + 1));

    for (int i = 0; i <= n; i++) {
        dp[i][0] = dp[i][i] = 1;
        for (int j = 1; j < i; j++) {
            dp[i][j] = dp[i - 1][j - 1] + dp[i - 1][j];
        }
    }

    return dp[n][r];
}
```

#### پیچیدگی زمانی

برای هر $i$ حداکثر $i$ خانه پر می‌کنیم، پس در مجموع $O(1 + 2 + \dots + n) = O(n^2)$ عملیات انجام می‌دهیم و به $O(n^2)$ حافظه نیاز داریم. مزیت این روش این است که هیچ تقسیمی در آن نیست و به همین دلیل به راحتی می‌توان همه‌ی محاسبات را به پیمانه‌ی یک عدد دلخواه (حتی غیر اول) انجام داد.

!!! tip "نکته"
    اگر فقط یک سطر خاص را می‌خواهیم، با نگه داشتن دو سطر آخر می‌توان حافظه را به $O(n)$ کاهش داد.

### محاسبه به پیمانه‌ی یک عدد اول

در بیشتر سوالات مسابقه‌ای جواب را به پیمانه‌ی عددی اول مانند $MOD = 10^9 + 7$ می‌خواهند و $n$ می‌تواند تا $10^6$ یا بیشتر باشد؛ در این شرایط جدول $O(n^2)$ قابل استفاده نیست. ایده این است که فاکتوریل‌ها را به پیمانه‌ی $MOD$ از قبل حساب کنیم:

$$\binom{n}{r} \equiv fact[n] \times invfact[r] \times invfact[n-r] \pmod{MOD}$$

که در آن $fact[i] = i!$ و $invfact[i] = (i!)^{-1}$ به پیمانه‌ی $MOD$ هستند.

در حساب پیمانه‌ای نمی‌توان مستقیم تقسیم کرد و به جای آن باید در [وارون ضربی](/Level2/fermat/) ضرب کنیم. چون $MOD$ اول است، طبق قضیه‌ی کوچک فرما وارون $a$ برابر $a^{MOD-2}$ است که با [توان دودویی](/Level2/power/) در $O(\log MOD)$ به دست می‌آید. برای این که به ازای هر $i$ یک بار توان دودویی نزنیم، فقط $invfact[MAX]$ را این‌طور حساب می‌کنیم و بقیه را از رابطه‌ی زیر به صورت نزولی به دست می‌آوریم:

$$invfact[i] = invfact[i+1] \times (i+1)$$

#### کد

```cpp linenums="1"

const int MOD = 1e9 + 7;
const int MAX = 1e6 + 5;

long long fact[MAX], invfact[MAX];

long long power(long long a, long long b) {
    long long res = 1;
    while (b) {
        if (b & 1) res = res * a % MOD;
        a = a * a % MOD;
        b >>= 1;
    }
    return res;
}

void init() {
    fact[0] = 1;
    for (int i = 1; i < MAX; i++)
        fact[i] = fact[i - 1] * i % MOD;

    invfact[MAX - 1] = power(fact[MAX - 1], MOD - 2); // (1)!
    for (int i = MAX - 2; i >= 0; i--)
        invfact[i] = invfact[i + 1] * (i + 1) % MOD; // (2)!
}

long long nCr(int n, int r) {
    if (r > n || r < 0) return 0;
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD;
}

int main() {
    init();
    cout << nCr(5, 2) << endl;       // 10
    cout << nCr(10, 3) << endl;      // 120
    cout << nCr(1000000, 500000) << endl;
}
```

1. تنها جایی که از توان دودویی استفاده می‌کنیم.

2. چون $(i+1)! = (i+1) \times i!$ است، داریم $\frac{1}{i!} = \frac{i+1}{(i+1)!}$.

#### پیچیدگی زمانی

پیش‌پردازش از $O(MAX + \log MOD)$ زمان می‌برد و بعد از آن هر پرسش $\binom{n}{r}$ در $O(1)$ جواب داده می‌شود.

!!! warning ""
    استفاده از قضیه‌ی کوچک فرما فقط وقتی درست است که $MOD$ اول باشد. اگر پیمانه اول نباشد، یا باید از جدول پاسکال استفاده کرد یا وارون را با الگوریتم اقلیدس توسعه‌یافته به دست آورد (آن هم فقط برای اعدادی که نسبت به پیمانه اول‌اند).
