## کاربردهای Stack در مسائل الگوریتمی

در فصل قبل با ساختمان داده‌ی **Stack** آشنا شدیم و دیدیم که این ساختمان داده از قانون **Last In First Out (LIFO)** پیروی می‌کند. اگرچه در کتابخانه‌ی STL کلاسی به نام `stack` وجود دارد، اما در بسیاری از مسابقات برنامه‌نویسی، برنامه‌نویسان حرفه‌ای ترجیح می‌دهند به جای آن از `vector` استفاده کنند. دلیل این موضوع آن است که `vector` علاوه بر داشتن همان عملیات‌های افزودن، حذف و دسترسی به عنصر آخر، امکانات بیشتری مانند پیمایش عناصر، استفاده از Iteratorها و سایر توابع عمومی STL را نیز در اختیار ما قرار می‌دهد و معمولاً سربار کمتری نیز نسبت به `stack` دارد. از آنجا که از نظر الگوریتمی هیچ تفاوتی میان این دو وجود ندارد، در تمام مثال‌های این فصل از `vector` به عنوان Stack استفاده خواهیم کرد.

## بررسی صحیح بودن پرانتزها

یکی از کلاسیک‌ترین کاربردهای Stack، بررسی صحیح بودن یک رشته‌ی شامل پرانتزها است. منظور از صحیح بودن این است که هر پرانتز باز دقیقاً یک پرانتز بسته‌ی متناظر داشته باشد و ترتیب بسته شدن پرانتزها نیز برعکس ترتیب باز شدن آن‌ها باشد. برای مثال رشته‌های زیر صحیح هستند.

```text
()
(()())
([]{})
```

اما رشته‌های زیر نامعتبرند.

```text
)(
([)]
(()
```

ایده‌ی حل مسئله بسیار ساده است. رشته را از چپ به راست پیمایش می‌کنیم. هرگاه به یک پرانتز باز برسیم، آن را داخل Stack قرار می‌دهیم. هنگام مشاهده‌ی یک پرانتز بسته، باید آخرین پرانتز بازی که هنوز بسته نشده است را بررسی کنیم؛ بنابراین اگر Stack خالی باشد یا نوع پرانتز موجود در انتهای آن با پرانتز بسته‌ی فعلی مطابقت نداشته باشد، رشته نامعتبر است. در غیر این صورت آخرین پرانتز باز از Stack حذف می‌شود. در پایان نیز اگر Stack خالی باشد، تمام پرانتزها به درستی بسته شده‌اند.

```cpp linenums="1"
#include <bits/stdc++.h>
using namespace std;

bool check(string s) {

    vector<char> st;

    for (char c : s) {

        if (c == '(' || c == '[' || c == '{')
            st.push_back(c);

        else { // (1)!

            if (st.empty())
                return false;

            if (c == ')' && st.back() != '(')
                return false;

            if (c == ']' && st.back() != '[')
                return false;

            if (c == '}' && st.back() != '{')
                return false;

            st.pop_back(); // (2)!
        }
    }

    return st.empty(); // (3)!
}
```

1. به یک پرانتز بسته رسیده‌ایم و باید آخرین پرانتز بازی که هنوز بسته نشده است را بررسی کنیم.
2. این دو پرانتز با یکدیگر متناظر هستند؛ بنابراین آخرین پرانتز باز از Stack حذف می‌شود.
3. اگر در پایان Stack خالی باشد، تمام پرانتزهای باز بسته شده‌اند.

از آنجا که رشته تنها یک بار پیمایش می‌شود و هر پرانتز دقیقاً یک بار وارد Stack شده و حداکثر یک بار نیز از آن خارج می‌شود، مجموع تعداد عملیات‌ها متناسب با طول رشته است؛ بنابراین مرتبه‌ی زمانی الگوریتم برابر با

$$
O(n)
$$

و حافظه‌ی موردنیاز آن نیز در بدترین حالت برابر با

$$
O(n)
$$

خواهد بود.

??? success "اثبات درستی"

    در هر لحظه، عناصر موجود در Stack دقیقاً پرانتزهای بازی هستند که تاکنون مشاهده شده‌اند اما هنوز بسته نشده‌اند. بنابراین هنگام مشاهده‌ی یک پرانتز بسته، تنها پرانتزی که می‌تواند با آن متناظر باشد آخرین پرانتز بازی است که هنوز بسته نشده است؛ زیرا در هر پرانتزگذاری صحیح، پرانتزها به صورت تو در تو بسته می‌شوند. اگر Stack خالی باشد یا نوع پرانتز موجود در انتهای آن با پرانتز بسته‌ی فعلی متفاوت باشد، هیچ تطابق معتبری وجود نخواهد داشت و رشته نامعتبر است. در غیر این صورت حذف آخرین پرانتز باز دقیقاً همان کاری است که در یک پرانتزگذاری صحیح اتفاق می‌افتد. در پایان نیز خالی بودن Stack معادل آن است که تمام پرانتزهای باز بسته شده باشند؛ بنابراین الگوریتم دقیقاً در همان حالتی مقدار `true` برمی‌گرداند که رشته دارای پرانتزگذاری صحیح باشد.
## نزدیک‌ترین عنصر بزرگ‌تر از سمت چپ (آقابالاسر)

یکی دیگر از مهم‌ترین کاربردهای Stack، پیدا کردن **نزدیک‌ترین عنصر بزرگ‌تر از سمت چپ** هر عنصر است که در بسیاری از منابع فارسی با نام **آقابالاسر** نیز شناخته می‌شود. در این مسئله، برای هر عنصر آرایه می‌خواهیم اولین عنصر بزرگ‌تر از آن را که در سمت چپش قرار دارد پیدا کنیم. برای مثال، اگر آرایه‌ی زیر را در نظر بگیریم

```text
3 7 5 8 4 6
```

پاسخ برابر خواهد بود با

```text
-1 -1 7 -1 8 8
```

زیرا برای عنصر `5` نزدیک‌ترین عنصر بزرگ‌تر در سمت چپ برابر `7` است و برای عنصر `6` نیز پاسخ `8` خواهد بود. واضح است که اگر برای هر خانه تمام عناصر سمت چپ را بررسی کنیم، مرتبه‌ی زمانی الگوریتم برابر با

$$
O(n^2)
$$

خواهد بود که برای آرایه‌های بزرگ مناسب نیست.

ایده‌ی اصلی استفاده از **Monotonic Stack** است. هنگام پردازش عنصر `a[i]`، تمام عناصری که کوچک‌تر یا مساوی آن هستند را از انتهای Stack حذف می‌کنیم؛ زیرا این عناصر دیگر نمی‌توانند پاسخ هیچ عنصر بعدی باشند. پس از پایان این حذف‌ها، اگر Stack خالی نباشد، عنصر انتهایی آن دقیقاً نزدیک‌ترین عنصر بزرگ‌تر از سمت چپ خواهد بود. سپس خود `a[i]` را نیز وارد Stack می‌کنیم تا برای عناصر بعدی مورد استفاده قرار گیرد.

```cpp linenums="1"
#include <bits/stdc++.h>
using namespace std;

int main() {

    vector<int> a = {3, 7, 5, 8, 4, 6};

    vector<int> st;

    for (int x : a) {

        while (!st.empty() && st.back() <= x) // (1)!
            st.pop_back();

        if (st.empty()) // (2)!
            cout << -1 << ' ';
        else
            cout << st.back() << ' '; // (3)!

        st.push_back(x); // (4)!
    }
}
```

1. تمام عناصری که از عنصر فعلی کوچک‌تر یا مساوی هستند حذف می‌شوند؛ زیرا دیگر نمی‌توانند پاسخ هیچ عنصر بعدی باشند.
2. اگر Stack خالی شود، یعنی هیچ عنصر بزرگ‌تری در سمت چپ وجود ندارد.
3. اولین عنصر باقی‌مانده در انتهای Stack، نزدیک‌ترین عنصر بزرگ‌تر از سمت چپ است.
4. عنصر فعلی برای استفاده در پاسخ عناصر بعدی وارد Stack می‌شود.

### چرا عناصر کوچک‌تر حذف می‌شوند؟

فرض کنید هنگام پردازش عنصر `x`، مقداری مانند `y` در انتهای Stack قرار دارد که

$$
y \le x
$$

باشد. از آنجا که `x` در سمت راست `y` قرار گرفته و حداقل به اندازه‌ی آن بزرگ است، هر عنصر جدیدی که در آینده پردازش شود، اگر بتواند از `y` استفاده کند، قطعاً می‌تواند از `x` نیز استفاده کند و از آنجا که `x` نزدیک‌تر است، همیشه انتخاب بهتری خواهد بود. بنابراین `y` دیگر هیچ‌گاه پاسخ هیچ خانه‌ای نخواهد شد و می‌توان آن را با خیال راحت حذف کرد.

از آنجا که هر عنصر دقیقاً یک بار وارد Stack می‌شود و حداکثر یک بار نیز از آن خارج می‌شود، مجموع تعداد عملیات‌های `push_back` و `pop_back` حداکثر برابر با

$$
2n
$$

خواهد بود؛ بنابراین مرتبه‌ی زمانی کل الگوریتم برابر با

$$
O(n)
$$

و حافظه‌ی موردنیاز آن برابر با

$$
O(n)
$$

است.

??? success "اثبات درستی"

    پس از پردازش هر عنصر، عناصر موجود در Stack به صورت نزولی مرتب شده‌اند و هیچ عنصر بی‌فایده‌ای در آن وجود ندارد. هنگام پردازش عنصر `a[i]`، تمام عناصر کوچک‌تر یا مساوی آن حذف می‌شوند؛ زیرا همان‌طور که گفته شد، دیگر هرگز پاسخ هیچ عنصر آینده‌ای نخواهند بود. بنابراین اگر پس از پایان حذف‌ها Stack خالی نباشد، اولین عنصر باقی‌مانده در انتهای آن نزدیک‌ترین عنصر بزرگ‌تر از `a[i]` در سمت چپ خواهد بود؛ زیرا تمام عناصر نزدیک‌تر که کوچک‌تر یا مساوی `a[i]` بوده‌اند حذف شده‌اند و هیچ عنصر بزرگ‌تر دیگری بین آن و `a[i]` وجود ندارد. بنابراین الگوریتم برای تمام خانه‌ها پاسخ صحیح را تولید می‌کند.

!!! note "نکته"

    با تغییر جهت پیمایش یا تغییر شرط داخل حلقه‌ی `while`، دقیقاً همین الگوریتم برای پیدا کردن نزدیک‌ترین عنصر کوچک‌تر از سمت چپ، نزدیک‌ترین عنصر بزرگ‌تر از سمت راست و نزدیک‌ترین عنصر کوچک‌تر از سمت راست نیز قابل استفاده است.

## بزرگ‌ترین مستطیل در هیستوگرام

یکی دیگر از مشهورترین کاربردهای **Monotonic Stack**، مسئله‌ی **Largest Rectangle in Histogram** است. در این مسئله، ارتفاع تعدادی ستون با عرض یک داده شده است و هدف، پیدا کردن بزرگ‌ترین مستطیلی است که بتوان آن را کاملاً داخل هیستوگرام رسم کرد. برای مثال اگر ارتفاع ستون‌ها برابر باشد با

```text
2 1 5 6 2 3
```

پاسخ برابر با `10` خواهد بود؛ زیرا می‌توان مستطیلی با ارتفاع `5` و عرض `2` رسم کرد.

اگر برای هر ستون، تمام ستون‌های سمت چپ و راست را بررسی کنیم تا بیشترین بازه‌ای که ارتفاع آن حداقل برابر ارتفاع ستون فعلی باشد را پیدا کنیم، مرتبه‌ی زمانی الگوریتم برابر با

$$
O(n^2)
$$

خواهد شد. اما با استفاده از Monotonic Stack می‌توان این مسئله را در زمان خطی حل کرد.

ایده‌ی اصلی این است که برای هر ستون، نزدیک‌ترین ستون کوچک‌تر از آن در سمت چپ و سمت راست را پیدا کنیم. اگر این دو اندیس را به ترتیب با

$$
L_i,\qquad R_i
$$

نمایش دهیم، آنگاه بزرگ‌ترین مستطیلی که ستون `i` کوتاه‌ترین ستون آن باشد، دارای عرض

$$
R_i-L_i-1
$$

و در نتیجه مساحت

$$
a_i\times(R_i-L_i-1)
$$

خواهد بود. بنابراین کافی است این مقدار را برای تمام ستون‌ها محاسبه کرده و بیشینه‌ی آن را گزارش کنیم.

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {

    vector<int> h = {2,1,5,6,2,3};
    int n = h.size();

    vector<int> L(n), R(n);
    vector<int> st;

    for (int i = 0; i < n; i++) {

        while (!st.empty() && h[st.back()] >= h[i]) // (1)!
            st.pop_back();

        if (st.empty())
            L[i] = -1;
        else
            L[i] = st.back();

        st.push_back(i);
    }

    st.clear();

    for (int i = n - 1; i >= 0; i--) {

        while (!st.empty() && h[st.back()] >= h[i]) // (2)!
            st.pop_back();

        if (st.empty())
            R[i] = n;
        else
            R[i] = st.back();

        st.push_back(i);
    }

    long long ans = 0;

    for (int i = 0; i < n; i++) {

        long long width = R[i] - L[i] - 1;
        ans = max(ans, width * h[i]);
    }

    cout << ans;
}
```

1. نزدیک‌ترین ستون کوچک‌تر از سمت چپ پیدا می‌شود.
2. نزدیک‌ترین ستون کوچک‌تر از سمت راست پیدا می‌شود.

هر ستون دقیقاً یک بار وارد Stack شده و حداکثر یک بار نیز از آن خارج می‌شود؛ بنابراین مجموع عملیات‌های انجام‌شده روی Stack خطی است و هر دو پیمایش در زمان

$$
O(n)
$$

انجام می‌شوند. در نتیجه، مرتبه‌ی زمانی کل الگوریتم برابر با

$$
O(n)
$$

و حافظه‌ی موردنیاز آن برابر با

$$
O(n)
$$

است.

??? success "اثبات درستی"

    برای هر ستون، اولین ستون کوچک‌تر در سمت چپ و راست، مرزهایی هستند که دیگر امکان گسترش مستطیل با ارتفاع ستون فعلی را از بین می‌برند. بنابراین بزرگ‌ترین مستطیلی که ستون `i` کوتاه‌ترین ستون آن باشد، دقیقاً بین این دو مرز قرار می‌گیرد و عرض آن برابر `R_i-L_i-1` خواهد بود. از آنجا که هر مستطیل موجود در هیستوگرام حداقل یک ستون با کمترین ارتفاع دارد، هنگام بررسی همان ستون، مساحت آن مستطیل نیز محاسبه خواهد شد؛ بنابراین بیشینه‌ی مساحت محاسبه‌شده دقیقاً برابر پاسخ مسئله است.

!!! note "نکته"

    در بسیاری از منابع، به جای محاسبه‌ی جداگانه‌ی آرایه‌های `L` و `R`، این مسئله تنها با **یک Stack** و یک پیمایش نیز حل می‌شود. اگرچه آن روش اندکی کوتاه‌تر است، اما روش ارائه‌شده در اینجا ساده‌تر بوده و ارتباط مستقیمی با ایده‌ی نزدیک‌ترین عنصر کوچک‌تر دارد.

## بیشینه‌ی Sliding Window

یکی دیگر از مسائل بسیار معروف که ارتباط نزدیکی با Stack و Deque دارد، مسئله‌ی **Sliding Window Maximum** است. در این مسئله آرایه‌ای به طول `n` و عددی به نام `k` داده می‌شود و باید برای هر بازه‌ی متوالی به طول `k`، بزرگ‌ترین عنصر آن بازه را پیدا کنیم. برای مثال اگر داشته باشیم

```text
a = [1, 3, -1, -3, 5, 3, 6, 7]
k = 3
```

پاسخ برابر خواهد بود با

```text
3 3 5 5 6 7
```

زیرا بیشینه‌ی بازه‌های

```text
[1,3,-1]
[3,-1,-3]
[-1,-3,5]
[-3,5,3]
[5,3,6]
[3,6,7]
```

به ترتیب برابر با مقادیر بالا هستند.

## روش اول: استفاده از `set`

یکی از ساده‌ترین راه‌ها، نگهداری عناصر پنجره‌ی فعلی داخل یک `set<pair<int,int>>` است. در این مجموعه، مؤلفه‌ی اول مقدار عنصر و مؤلفه‌ی دوم اندیس آن است تا در صورت وجود عناصر مساوی نیز بتوان آن‌ها را از یکدیگر تشخیص داد. در هر مرحله، عنصر جدید را وارد مجموعه کرده و عنصری که از پنجره خارج می‌شود را حذف می‌کنیم. از آنجا که عناصر Set همواره مرتب هستند، بزرگ‌ترین عنصر همیشه در انتهای مجموعه قرار دارد.

```cpp linenums="1"
#include <bits/stdc++.h>
using namespace std;

int main() {

    vector<int> a = {1,3,-1,-3,5,3,6,7};
    int k = 3;

    set<pair<int,int>> st;

    for (int i = 0; i < (int)a.size(); i++) {

        st.insert({a[i], i});

        if (i >= k)
            st.erase({a[i-k], i-k}); // (1)!

        if (i >= k - 1)
            cout << prev(st.end())->first << ' '; // (2)!
    }
}
```

1. عنصری که از پنجره خارج شده است از مجموعه حذف می‌شود.
2. آخرین عنصر Set همیشه بزرگ‌ترین مقدار پنجره است.

در این روش، هر عملیات درج و حذف در `set` دارای مرتبه‌ی زمانی

$$
O(\log k)
$$

است و برای هر عنصر دقیقاً یک بار انجام می‌شود؛ بنابراین مرتبه‌ی زمانی کل الگوریتم برابر با

$$
O(n\log k)
$$

خواهد بود.

## روش دوم: استفاده از Monotonic Deque

اگر تنها به بیشینه‌ی هر پنجره نیاز داشته باشیم، می‌توان مسئله را سریع‌تر حل کرد. ایده‌ی اصلی این است که به جای نگهداری تمام عناصر پنجره، تنها عناصری را نگه داریم که هنوز ممکن است در آینده پاسخ باشند. برای این کار از یک **Deque** استفاده می‌کنیم که اندیس عناصر را به صورت نزولی از نظر مقدار نگهداری می‌کند. هرگاه عنصر جدیدی وارد پنجره شود، تمام عناصر کوچک‌تر یا مساوی آن از انتهای Deque حذف می‌شوند؛ زیرا دیگر هرگز نمی‌توانند بیشینه‌ی هیچ پنجره‌ی آینده‌ای باشند. همچنین اگر اندیس عنصر ابتدای Deque از پنجره خارج شده باشد، آن نیز حذف می‌شود.

```cpp linenums="1"
#include <bits/stdc++.h>
using namespace std;

int main() {

    vector<int> a = {1,3,-1,-3,5,3,6,7};
    int k = 3;

    deque<int> dq;

    for (int i = 0; i < (int)a.size(); i++) {

        while (!dq.empty() && a[dq.back()] <= a[i]) // (1)!
            dq.pop_back();

        dq.push_back(i);

        while (!dq.empty() && dq.front() <= i - k) // (2)!
            dq.pop_front();

        if (i >= k - 1)
            cout << a[dq.front()] << ' '; // (3)!
    }
}
```

1. تمام عناصری که از عنصر جدید کوچک‌تر یا مساوی هستند حذف می‌شوند؛ زیرا دیگر پاسخ هیچ پنجره‌ای نخواهند بود.
2. اگر عنصر ابتدای Deque از پنجره خارج شده باشد، حذف می‌شود.
3. عنصر ابتدای Deque همیشه بیشینه‌ی پنجره‌ی فعلی است.

هر اندیس دقیقاً یک بار وارد Deque شده و حداکثر یک بار نیز از آن خارج می‌شود؛ بنابراین مجموع عملیات‌های انجام‌شده روی Deque حداکثر برابر با

$$
2n
$$

است و در نتیجه مرتبه‌ی زمانی کل الگوریتم برابر با

$$
O(n)
$$

و حافظه‌ی موردنیاز آن برابر با

$$
O(k)
$$

خواهد بود.

??? success "اثبات درستی"

    در هر لحظه، اندیس‌های موجود در Deque متعلق به عناصر پنجره‌ی فعلی هستند و مقادیر متناظر با آن‌ها به صورت نزولی مرتب شده‌اند. هنگام ورود یک عنصر جدید، تمام عناصر کوچک‌تر یا مساوی آن حذف می‌شوند؛ زیرا تا زمانی که عنصر جدید در پنجره حضور دارد، آن عناصر هرگز نمی‌توانند بیشینه‌ی هیچ پنجره‌ای باشند. همچنین هرگاه اندیس ابتدای Deque از بازه‌ی فعلی خارج شود، حذف می‌شود تا فقط عناصر موجود در پنجره باقی بمانند. بنابراین اولین اندیس موجود در Deque همواره متعلق به بزرگ‌ترین عنصر پنجره‌ی فعلی است و الگوریتم برای تمام پنجره‌ها پاسخ صحیح را تولید می‌کند.

## مقایسه‌ی دو روش

| روش | زمان | حافظه |
| :--- | :---: | :---: |
| `set<pair<int,int>>` | $O(n\log k)$ | $O(k)$ |
| Monotonic Deque | $O(n)$ | $O(k)$ |

!!! tip "کدام روش بهتر است؟"

    اگر تنها به بیشینه یا کمینه‌ی هر پنجره نیاز داشته باشیم، استفاده از **Monotonic Deque** بهترین انتخاب است و مرتبه‌ی زمانی خطی دارد. اما اگر علاوه بر بیشینه، به عملیات دیگری مانند حذف یا جستجوی دلخواه روی عناصر پنجره نیز نیاز داشته باشیم، استفاده از `set` می‌تواند مناسب‌تر باشد.

## جمع‌بندی

در این فصل با مهم‌ترین کاربردهای Stack در مسائل الگوریتمی آشنا شدیم. ابتدا دیدیم که چگونه می‌توان با استفاده از Stack، درستی یک پرانتزگذاری را تنها با یک پیمایش بررسی کرد. سپس با ایده‌ی **Monotonic Stack** آشنا شدیم و مشاهده کردیم که با حذف عناصر بی‌فایده می‌توان مسائلی مانند پیدا کردن نزدیک‌ترین عنصر بزرگ‌تر از سمت چپ را در زمان خطی حل کرد. در پایان نیز مسئله‌ی مشهور **Sliding Window Maximum** را با دو روش مبتنی بر `set` و `deque` بررسی کردیم و دیدیم که استفاده از Monotonic Deque مرتبه‌ی زمانی را از

$$
O(n\log k)
$$

به

$$
O(n)
$$

کاهش می‌دهد. این ایده‌ها پایه‌ی بسیاری از مسائل پیشرفته‌تر برنامه‌نویسی مسابقه‌ای هستند و در فصل‌های بعدی نیز بارها با آن‌ها روبه‌رو خواهیم شد.
