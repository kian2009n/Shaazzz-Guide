در [بخش قبل](/Level2/ds_basic/) با استک آشنا شدیم و دیدیم که از قانون «آخرین ورودی، اولین خروجی» پیروی می‌کند. در این بخش چند مسئله‌ی کلاسیک را می‌بینیم که با همین داده‌ساختار ساده در زمان خطی حل می‌شوند. در کدها به جای `#!cpp stack` از `#!cpp vector` استفاده می‌کنیم؛ `#!cpp push_back`، `#!cpp pop_back` و `#!cpp back` دقیقا همان کار استک را می‌کنند و علاوه بر آن امکان پیمایش اعضا را هم داریم.

### بررسی درستی پرانتزها

#### مسئله

رشته‌ای از پرانتزهای `()`، `[]` و `{}` داده شده است. می‌خواهیم بفهمیم پرانتزگذاری درست است یا نه؛ یعنی هر پرانتز باز دقیقا یک پرانتز بسته‌ی هم‌نوع داشته باشد و پرانتزها به صورت تودرتو بسته شوند. مثلا `()`، `(()())` و `([]{})` درست و `)(`، `([)]` و `(()` نادرست‌اند.

#### راه حل

رشته را از چپ به راست می‌خوانیم. هر پرانتز باز را در استک می‌گذاریم. وقتی به پرانتز بسته رسیدیم، باید با آخرین پرانتز بازی که هنوز بسته نشده جفت شود؛ آن پرانتز همان عضو بالای استک است. پس اگر استک خالی باشد یا نوع عضو بالایی با پرانتز بسته‌ی فعلی نخواند، رشته نادرست است و در غیر این صورت عضو بالایی را حذف می‌کنیم. در پایان، رشته درست است اگر و فقط اگر استک خالی باشد.

```cpp linenums="1"

bool check(string s) {
    vector<char> st;
    for (char c : s) {
        if (c == '(' || c == '[' || c == '{') {
            st.push_back(c);
        } else { // (1)!
            if (st.empty())
                return false;
            if (c == ')' && st.back() != '(') return false;
            if (c == ']' && st.back() != '[') return false;
            if (c == '}' && st.back() != '{') return false;
            st.pop_back(); // (2)!
        }
    }
    return st.empty(); // (3)!
}
```

1. به یک پرانتز بسته رسیده‌ایم و باید آن را با آخرین پرانتز باز جفت کنیم.

2. این دو با هم جفت شدند؛ پرانتز باز را از استک برمی‌داریم.

3. اگر پرانتز بازی بدون جفت مانده باشد، رشته نادرست است.

??? success "اثبات درستی"
    در هر لحظه اعضای استک دقیقا پرانتزهای بازی هستند که هنوز بسته نشده‌اند. در یک پرانتزگذاری درست، پرانتزها تودرتو بسته می‌شوند؛ پس تنها پرانتزی که می‌تواند با پرانتز بسته‌ی فعلی جفت شود، آخرین پرانتز باز یعنی عضو بالای استک است. اگر چنین جفتی ممکن نباشد هیچ پرانتزگذاری درستی وجود ندارد و اگر ممکن باشد، حذف آن دقیقا همان چیزی است که در پرانتزگذاری درست اتفاق می‌افتد. در پایان هم خالی بودن استک یعنی همه‌ی پرانتزهای باز بسته شده‌اند.

#### پیچیدگی زمانی

هر پرانتز دقیقا یک بار وارد استک و حداکثر یک بار از آن خارج می‌شود، پس زمان $O(n)$ و حافظه در بدترین حالت $O(n)$ است.

### نزدیک‌ترین عضو بزرگ‌تر سمت چپ

#### مسئله

آرایه‌ی $a_1, \dots, a_n$ داده شده است. برای هر عضو می‌خواهیم نزدیک‌ترین عضو سمت چپش را پیدا کنیم که از آن بزرگ‌تر باشد (در منابع فارسی به این مسئله «آقابالاسر» هم می‌گویند). مثلا برای آرایه‌ی $3, 7, 5, 8, 4, 6$ جواب $-1, -1, 7, -1, 8, 8$ است؛ چون آقابالاسر $5$ عدد $7$ و آقابالاسر $6$ عدد $8$ است و $3$، $7$ و $8$ آقابالاسر ندارند.

اگر برای هر خانه همه‌ی اعضای سمت چپ را بررسی کنیم، زمان $O(n^2)$ می‌شود که برای آرایه‌های بزرگ مناسب نیست.

#### راه حل

از یک استک یکنوا (Monotonic Stack) استفاده می‌کنیم. هنگام پردازش $a_i$، تمام اعضایی که کوچک‌تر یا مساوی $a_i$ هستند را از بالای استک حذف می‌کنیم، چون این اعضا دیگر نمی‌توانند جواب هیچ عضو بعدی باشند. بعد از این حذف‌ها، اگر استک خالی نباشد عضو بالایی آن دقیقا جواب $a_i$ است. سپس خود $a_i$ را هم وارد استک می‌کنیم تا برای اعضای بعدی استفاده شود.

??? success "چرا اعضای کوچک‌تر را حذف می‌کنیم؟"
    فرض کنید هنگام پردازش $x$، عضوی مانند $y \leq x$ در استک باشد. چون $x$ سمت راست $y$ است و حداقل به اندازه‌ی آن بزرگ است، هر عضو بعدی که بتواند $y$ را به عنوان آقابالاسر انتخاب کند، می‌تواند $x$ را هم انتخاب کند و $x$ نزدیک‌تر است. پس $y$ دیگر هیچ‌وقت جواب هیچ خانه‌ای نمی‌شود و حذف آن مشکلی ایجاد نمی‌کند.

    در نتیجه بعد از پردازش هر عضو، اعضای استک از پایین به بالا اکیدا نزولی هستند و هیچ عضو بی‌فایده‌ای در آن نیست. پس وقتی حذف‌ها تمام شد، عضو بالایی نزدیک‌ترین عضو بزرگ‌تر از $a_i$ است: همه‌ی اعضای نزدیک‌تر یا کوچک‌تر یا مساوی $a_i$ بوده‌اند و حذف شده‌اند.

```cpp linenums="1"

int main() {
    vector<int> a = {3, 7, 5, 8, 4, 6};
    vector<int> st;

    for (int x : a) {
        while (!st.empty() && st.back() <= x) // (1)!
            st.pop_back();

        if (st.empty()) // (2)!
            cout << -1 << ' ';
        else
            cout << st.back() << ' ';

        st.push_back(x); // (3)!
    }
}
```

1. اعضایی که از $x$ کوچک‌تر یا مساوی‌اند دیگر به درد هیچ عضو بعدی نمی‌خورند.

2. اگر استک خالی شد، هیچ عضو بزرگ‌تری در سمت چپ وجود ندارد.

3. $x$ را برای اعضای بعدی در استک می‌گذاریم.

#### پیچیدگی زمانی

هر عضو دقیقا یک بار وارد استک و حداکثر یک بار از آن خارج می‌شود، پس مجموع عملیات‌ها حداکثر $2n$ و زمان $O(n)$ است.

!!! tip "نکته"
    با تغییر جهت پیمایش یا شرط داخل `#!cpp while`، همین الگوریتم نزدیک‌ترین عضو کوچک‌تر سمت چپ و نزدیک‌ترین عضو بزرگ‌تر یا کوچک‌تر سمت راست را هم پیدا می‌کند. اگر به جای مقدار، اندیس اعضا را در استک بگذاریم، فاصله‌ها را هم می‌توانیم حساب کنیم.

### تکنیک سهم

#### مسئله

آرایه‌ی $a_1, \dots, a_n$ داده شده است. مجموع کمینه‌ی **همه‌ی** زیرآرایه‌های آن را می‌خواهیم؛ یعنی

$$\sum_{1 \leq l \leq r \leq n} \min(a_l, a_{l+1}, \dots, a_r)$$

مثلا برای آرایه‌ی $3, 1, 2, 4$ زیرآرایه‌ها و کمینه‌هایشان این‌ها هستند: $[3] \to 3$، $[1] \to 1$، $[2] \to 2$، $[4] \to 4$، $[3, 1] \to 1$، $[1, 2] \to 1$، $[2, 4] \to 2$، $[3, 1, 2] \to 1$، $[1, 2, 4] \to 1$ و $[3, 1, 2, 4] \to 1$؛ پس جواب $17$ است.

تعداد زیرآرایه‌ها $O(n^2)$ است، پس حتی شمردن تک‌تک آن‌ها هم برای $n = 10^5$ کند است.

#### راه حل

به جای این که روی زیرآرایه‌ها حلقه بزنیم و کمینه‌ی هر کدام را پیدا کنیم، سوال را برعکس می‌پرسیم: **هر عضو $a_i$ کمینه‌ی چند زیرآرایه است؟** اگر این تعداد را $c_i$ بنامیم، هر زیرآرایه دقیقا یک بار (به حساب کمینه‌اش) شمرده می‌شود و جواب برابر $\sum a_i \times c_i$ است. به این ایده که «به جای جمع زدن روی حالت‌ها، سهم هر عضو را جداگانه حساب کنیم» تکنیک سهم (Contribution Technique) می‌گویند و در سوالات شمارشی زیادی به کار می‌آید.

حالا $c_i$ را حساب می‌کنیم. زیرآرایه‌ی $[l, r]$ دقیقا وقتی کمینه‌اش $a_i$ است که $l \leq i \leq r$ باشد و هیچ عضو کوچک‌تری از $a_i$ در آن نباشد. اگر $L_i$ اندیس نزدیک‌ترین عضو کوچک‌تر در سمت چپ $i$ باشد (و اگر نبود $0$) و $R_i$ اندیس نزدیک‌ترین عضو کوچک‌تر در سمت راست (و اگر نبود $n+1$)، آنگاه $l$ می‌تواند هر کدام از $L_i + 1, \dots, i$ و $r$ می‌تواند هر کدام از $i, \dots, R_i - 1$ باشد. این دو انتخاب مستقل‌اند، پس

$$c_i = (i - L_i) \times (R_i - i)$$

و $L_i$ و $R_i$ را دقیقا با همان استک یکنوای مسئله‌ی قبل (این بار برای «کوچک‌تر» به جای «بزرگ‌تر») در $O(n)$ پیدا می‌کنیم.

!!! danger "اعضای برابر"
    اگر در آرایه اعضای برابر داشته باشیم، باید مراقب باشیم هر زیرآرایه فقط یک بار شمرده شود. مثلا در آرایه‌ی $2, 2, 2$ زیرآرایه‌ی $[1, 3]$ کمینه‌اش $2$ است، اما کدام $2$؟ اگر برای هر دو طرف «اکیدا کوچک‌تر» بگیریم، برای هر سه عضو $L_i = 0$ و $R_i = 4$ می‌شود و این زیرآرایه سه بار شمرده می‌شود (جواب $20$ به جای $12$).

    راه حل این است که در یک طرف «اکیدا کوچک‌تر» و در طرف دیگر «کوچک‌تر یا مساوی» بگیریم؛ مثلا $L_i$ نزدیک‌ترین عضو **اکیدا کوچک‌تر** در چپ و $R_i$ نزدیک‌ترین عضو **کوچک‌تر یا مساوی** در راست باشد. این یعنی هر زیرآرایه را به حساب **چپ‌ترین** کمینه‌اش می‌گذاریم و هر زیرآرایه دقیقا یک چپ‌ترین کمینه دارد. در کد، این تفاوت فقط در شرط `#!cpp while` دو پیمایش دیده می‌شود.

```cpp linenums="1"

int main() {
    vector<int> a = {3, 1, 2, 4};
    int n = a.size();

    vector<int> L(n), R(n), st;

    for (int i = 0; i < n; i++) { // (1)!
        while (!st.empty() && a[st.back()] >= a[i])
            st.pop_back();
        L[i] = st.empty() ? -1 : st.back();
        st.push_back(i);
    }

    st.clear();
    for (int i = n - 1; i >= 0; i--) { // (2)!
        while (!st.empty() && a[st.back()] > a[i])
            st.pop_back();
        R[i] = st.empty() ? n : st.back();
        st.push_back(i);
    }

    long long ans = 0;
    for (int i = 0; i < n; i++)
        ans += 1LL * a[i] * (i - L[i]) * (R[i] - i); // (3)!

    cout << ans << endl; // 17
}
```

1. نزدیک‌ترین عضو **اکیدا کوچک‌تر** در سمت چپ؛ اعضای بزرگ‌تر یا مساوی حذف می‌شوند. اندیس‌ها از صفر شروع شده‌اند، پس «وجود ندارد» را با $-1$ نشان می‌دهیم.

2. نزدیک‌ترین عضو **کوچک‌تر یا مساوی** در سمت راست؛ این بار فقط اعضای اکیدا بزرگ‌تر حذف می‌شوند. اگر وجود نداشت $R_i = n$.

3. سهم عضو $i$: مقدارش ضرب در تعداد زیرآرایه‌هایی که کمینه‌شان است. جواب می‌تواند بزرگ شود، پس در `#!cpp long long` جمع می‌زنیم.

#### پیچیدگی زمانی

دو پیمایش با استک یکنوا و یک حلقه‌ی ساده داریم؛ پس زمان و حافظه $O(n)$ است.

!!! tip "نکته"
    همین ایده با تغییر جهت نامساوی‌ها «مجموع بیشینه‌ی زیرآرایه‌ها» را هم می‌دهد و با کم کردن این دو، مجموع «بیشینه منهای کمینه» روی همه‌ی زیرآرایه‌ها به دست می‌آید. در سوالات دیگر هم هر وقت لازم شد چیزی را روی همه‌ی زیرآرایه‌ها جمع بزنید، اول بپرسید «سهم هر عضو چقدر است؟».

### بزرگ‌ترین مستطیل در هیستوگرام

#### مسئله

ارتفاع $n$ ستون با عرض یک داده شده است. مساحت بزرگ‌ترین مستطیلی که کاملا داخل این هیستوگرام جا شود چقدر است؟ مثلا برای ارتفاع‌های $2, 1, 5, 6, 2, 3$ جواب $10$ است (مستطیلی به ارتفاع $5$ و عرض $2$).

#### راه حل

اگر برای هر ستون، به چپ و راست برویم تا جایی که ارتفاع ستون‌ها حداقل برابر ارتفاع آن باشد، زمان $O(n^2)$ می‌شود. اما با ایده‌ی بخش قبل می‌توان آن را خطی کرد: برای هر ستون $i$، اندیس نزدیک‌ترین ستون کوتاه‌تر در سمت چپ را $L_i$ و در سمت راست را $R_i$ می‌نامیم. بزرگ‌ترین مستطیلی که ستون $i$ کوتاه‌ترین ستون آن است، دقیقا بین این دو مرز قرار می‌گیرد و مساحت آن $h_i \times (R_i - L_i - 1)$ است. هر مستطیل داخل هیستوگرام حداقل یک ستون کوتاه‌ترین دارد، پس بیشینه‌ی این مقدار روی همه‌ی ستون‌ها جواب مسئله است.

```cpp linenums="1"

int main() {
    vector<int> h = {2, 1, 5, 6, 2, 3};
    int n = h.size();

    vector<int> L(n), R(n), st;

    for (int i = 0; i < n; i++) { // (1)!
        while (!st.empty() && h[st.back()] >= h[i])
            st.pop_back();
        L[i] = st.empty() ? -1 : st.back();
        st.push_back(i);
    }

    st.clear();
    for (int i = n - 1; i >= 0; i--) { // (2)!
        while (!st.empty() && h[st.back()] >= h[i])
            st.pop_back();
        R[i] = st.empty() ? n : st.back();
        st.push_back(i);
    }

    long long ans = 0;
    for (int i = 0; i < n; i++)
        ans = max(ans, 1LL * h[i] * (R[i] - L[i] - 1));

    cout << ans << endl;
}
```

1. نزدیک‌ترین ستون کوتاه‌تر در سمت چپ؛ این بار اندیس‌ها را در استک می‌گذاریم. اگر وجود نداشت $L_i = -1$.

2. همان کار از سمت راست؛ اگر وجود نداشت $R_i = n$.

#### پیچیدگی زمانی

هر دو پیمایش مانند بخش قبل $O(n)$ هستند، پس کل الگوریتم $O(n)$ زمان و $O(n)$ حافظه می‌برد.

!!! tip "نکته"
    این مسئله را می‌توان با یک استک و یک پیمایش هم حل کرد (هنگام حذف هر ستون از استک، مساحت مستطیل آن را حساب می‌کنیم)، اما روش بالا ساده‌تر است و ارتباط مستقیمش با مسئله‌ی قبل روشن است.

### بیشینه‌ی پنجره‌ی لغزان

#### مسئله

آرایه‌ای به طول $n$ و عدد $k$ داده شده است. برای هر بازه‌ی متوالی به طول $k$ (پنجره‌ی لغزان یا Sliding Window)، بزرگ‌ترین عضو آن را می‌خواهیم. مثلا برای آرایه‌ی $1, 3, -1, -3, 5, 3, 6, 7$ و $k = 3$ جواب $3, 3, 5, 5, 6, 7$ است.

#### راه حل اول: ست

ساده‌ترین راه این است که اعضای پنجره‌ی فعلی را در یک `#!cpp set<pair<int, int>>` نگه داریم که مولفه‌ی اول مقدار و مولفه‌ی دوم اندیس است (تا اعضای مساوی از هم تشخیص داده شوند). در هر قدم عضو جدید را اضافه و عضوی که از پنجره بیرون رفته را حذف می‌کنیم؛ بزرگ‌ترین عضو همیشه آخرین عضو ست است.

```cpp linenums="1"

int main() {
    vector<int> a = {1, 3, -1, -3, 5, 3, 6, 7};
    int k = 3;

    set<pair<int, int>> st;
    for (int i = 0; i < (int) a.size(); i++) {
        st.insert({a[i], i});
        if (i >= k)
            st.erase({a[i - k], i - k}); // (1)!
        if (i >= k - 1)
            cout << prev(st.end())->first << ' '; // (2)!
    }
}
```

1. عضوی که از پنجره خارج شده را حذف می‌کنیم.

2. آخرین عضو ست، بیشینه‌ی پنجره‌ی فعلی است.

هر عضو یک بار درج و یک بار حذف می‌شود و هر عملیات ست $O(\log k)$ است؛ پس زمان کل $O(n \log k)$ است.

#### راه حل دوم: دکیو یکنوا

اگر فقط بیشینه را بخواهیم، می‌توان سریع‌تر عمل کرد. مثل مسئله‌ی آقابالاسر، به جای همه‌ی اعضای پنجره فقط اعضایی را نگه می‌داریم که هنوز ممکن است در آینده بیشینه شوند. در یک دکیو، اندیس اعضا را طوری نگه می‌داریم که مقادیرشان از جلو به عقب نزولی باشد:

+ وقتی عضو جدید $a_i$ می‌آید، همه‌ی اعضای کوچک‌تر یا مساوی آن را از عقب دکیو حذف می‌کنیم، چون تا وقتی $a_i$ در پنجره است هیچ‌وقت بیشینه نمی‌شوند.
+ اگر اندیس جلوی دکیو از پنجره بیرون رفته باشد ($\leq i - k$)، آن را از جلو حذف می‌کنیم.

به این ترتیب جلوی دکیو همیشه بیشینه‌ی پنجره‌ی فعلی است.

```cpp linenums="1"

int main() {
    vector<int> a = {1, 3, -1, -3, 5, 3, 6, 7};
    int k = 3;

    deque<int> dq;
    for (int i = 0; i < (int) a.size(); i++) {
        while (!dq.empty() && a[dq.back()] <= a[i]) // (1)!
            dq.pop_back();
        dq.push_back(i);

        if (dq.front() <= i - k) // (2)!
            dq.pop_front();

        if (i >= k - 1)
            cout << a[dq.front()] << ' '; // (3)!
    }
}
```

1. اعضایی که از عضو جدید کوچک‌تر یا مساوی‌اند، دیگر بیشینه‌ی هیچ پنجره‌ای نمی‌شوند.

2. عضو جلوی دکیو از پنجره خارج شده است.

3. جلوی دکیو همیشه بیشینه‌ی پنجره‌ی فعلی است.

هر اندیس دقیقا یک بار وارد دکیو و حداکثر یک بار خارج می‌شود، پس زمان $O(n)$ و حافظه $O(k)$ است.

!!! tip "کدام روش؟"
    اگر فقط بیشینه یا کمینه‌ی هر پنجره را می‌خواهید، دکیو یکنوا بهترین انتخاب است. اما اگر علاوه بر آن به عملیات دیگری روی اعضای پنجره (مثل حذف دلخواه یا پیدا کردن $k$امین عضو) نیاز دارید، ست انعطاف بیشتری دارد.
