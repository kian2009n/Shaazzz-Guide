در [بخش قبل](/Level2/digraph/) با گراف جهت‌دار آشنا شدیم. در خیلی از مسائل، علاوه بر جهت‌دار بودن، گراف ویژگی مهم دیگری هم دارد: هیچ دوری در آن نیست؛ یعنی از هیچ راسی نمی‌توان با دنبال کردن جهت یال‌ها دوباره به خودش برگشت. به چنین گرافی گراف جهت‌دار بدون دور (Directed Acyclic Graph) یا به اختصار DAG می‌گوییم. پیش‌نیاز درس‌های دانشگاه، وابستگی فایل‌های یک پروژه و ترتیب انجام کارها نمونه‌هایی از چیزهایی هستند که به صورت DAG مدل می‌شوند.

```text
1 -----> 2 -----> 4          1 -----> 2
 \       |                   ^        |
  \      v                   |        v
   ----> 3 ----> 5           +------- 3
```

گراف سمت چپ یک DAG است، اما گراف سمت راست نیست؛ چون از $1$ می‌توان به $2$، بعد $3$ و دوباره $1$ رسید.

### ترتیب توپولوژیک

نبودن دور باعث می‌شود بتوان راس‌ها را طوری در یک ردیف چید که همه‌ی یال‌ها از راس‌های زودتر به راس‌های دیرتر بروند. به بیان دقیق‌تر، ترتیبی از راس‌ها که برای هر یال $u \rightarrow v$ راس $u$ قبل از $v$ بیاید، ترتیب توپولوژیک (Topological Ordering) نام دارد.

```text
1 -----> 2
|        |
v        v
3 -----> 4
```

برای گراف بالا ترتیب‌های $1, 2, 3, 4$ و $1, 3, 2, 4$ هر دو معتبرند، اما $2, 1, 3, 4$ معتبر نیست چون یال $1 \rightarrow 2$ داریم ولی $2$ قبل از $1$ آمده است. دقت کنید که یک DAG معمولا چند ترتیب توپولوژیک مختلف دارد.

!!! warning ""
    ترتیب توپولوژیک فقط برای DAG وجود دارد. اگر گراف دور داشته باشد، راس‌های روی دور را به هیچ ترتیبی نمی‌توان چید که همه‌ی یال‌های دور رو به جلو باشند. پس اول باید بتوانیم وجود دور را تشخیص دهیم.

### تشخیص دور با DFS

در [DFS](/Level2/dfs/) به هر راس یکی از سه رنگ را می‌دهیم:

+ **سفید:** هنوز دیده نشده است.
+ **خاکستری:** وارد آن شده‌ایم ولی هنوز از آن خارج نشده‌ایم (روی مسیر فعلی DFS است).
+ **سیاه:** پردازش آن کاملا تمام شده است.

وقتی وارد راسی می‌شویم آن را خاکستری و وقتی همه‌ی یال‌های خروجی‌اش را بررسی کردیم سیاه می‌کنیم. اگر در میانه‌ی کار به یالی رسیدیم که به یک راس خاکستری می‌رود، یعنی به یکی از راس‌های مسیر فعلی برگشته‌ایم و گراف دور دارد.

```cpp linenums="1"

const int MAXN = 100000;

vector<int> adj[MAXN];
int color[MAXN]; // (1)!

bool hasCycle(int v) {
    color[v] = 1;
    for (int u : adj[v]) {
        if (color[u] == 1) // (2)!
            return true;
        if (color[u] == 0 && hasCycle(u))
            return true;
    }
    color[v] = 2;
    return false;
}
```

1. مقدار $0$ سفید، $1$ خاکستری و $2$ سیاه است.

2. یال به یک راس خاکستری، یعنی راسی که هنوز روی مسیر فعلی است: دور پیدا شد.

??? success "اثبات درستی"
    اگر به راس خاکستری $u$ برسیم، $u$ هنوز از پشته‌ی بازگشت خارج نشده، پس مسیری از $u$ به راس فعلی طی کرده‌ایم و با این یال به $u$ برمی‌گردیم؛ یعنی یک دور داریم. برعکس، اگر گراف دور داشته باشد، اولین راس آن دور که DFS واردش می‌شود را $v$ بنامید. تا وقتی $v$ خاکستری است، DFS همه‌ی راس‌های قابل دسترس از $v$ (از جمله بقیه‌ی راس‌های دور) را می‌بیند و در نهایت از راس قبل از $v$ روی دور، یالی به $v$ خاکستری بررسی می‌شود. پس الگوریتم دقیقا وقتی دور گزارش می‌کند که گراف دور داشته باشد.

مثل هر DFS دیگری، پیچیدگی زمانی $O(n + m)$ است. برای بررسی کل گراف باید `#!cpp hasCycle` را از همه‌ی راس‌های سفید صدا بزنیم.

### مرتب‌سازی توپولوژیک با DFS

حالا فرض کنید گراف DAG است. ساده‌ترین راه برای پیدا کردن ترتیب توپولوژیک، استفاده از زمان خروج DFS است: هر راس را وقتی پردازشش تمام شد (یعنی هنگام خروج از آن) به انتهای یک آرایه اضافه می‌کنیم و در پایان آرایه را برعکس می‌کنیم.

```cpp linenums="1"

const int MAXN = 100000;

vector<int> adj[MAXN];
bool visited[MAXN];
vector<int> topo;

void dfs(int v) {
    visited[v] = true;
    for (int u : adj[v])
        if (!visited[u])
            dfs(u);
    topo.push_back(v); // (1)!
}

int main() {
    // خواندن گراف

    for (int i = 1; i <= n; i++)
        if (!visited[i])
            dfs(i);

    reverse(topo.begin(), topo.end()); // (2)!
}
```

1. راس را هنگام خروج، یعنی بعد از پردازش همه‌ی راس‌های قابل دسترس از آن، اضافه می‌کنیم.

2. در آرایه‌ی اولیه مقصد هر یال قبل از مبدأ آن است؛ با برعکس کردن، ترتیب درست می‌شود.

??? success "اثبات درستی"
    نشان می‌دهیم برای هر یال $u \rightarrow v$، راس $v$ زودتر از $u$ وارد `#!cpp topo` می‌شود. دو حالت داریم: اگر هنگام رسیدن به $u$ راس $v$ هنوز دیده نشده باشد، DFS قبل از خروج از $u$ وارد $v$ می‌شود و از آن خارج می‌شود؛ پس $v$ زودتر اضافه می‌شود. اگر $v$ قبلا دیده شده باشد، چون گراف دور ندارد $v$ نمی‌تواند روی مسیر فعلی (خاکستری) باشد، پس پردازش آن تمام شده و قبلا اضافه شده است. در هر دو حالت $v$ قبل از $u$ است و بعد از برعکس کردن آرایه، $u$ قبل از $v$ قرار می‌گیرد.

پیچیدگی زمانی $O(n + m)$ و حافظه $O(n)$ است.

### الگوریتم کان

روش دیگر، الگوریتم کان (Kahn) است که بر اساس درجه‌ی ورودی کار می‌کند. راسی که درجه‌ی ورودی صفر دارد هیچ پیش‌نیازی ندارد و می‌تواند اول ترتیب بیاید. پس:

1. همه‌ی راس‌های با درجه‌ی ورودی صفر را در یک صف می‌گذاریم.
2. راسی از صف برمی‌داریم، به جواب اضافه می‌کنیم و آن را از گراف حذف می‌کنیم؛ یعنی درجه‌ی ورودی همه‌ی همسایه‌هایش را یکی کم می‌کنیم.
3. هر همسایه‌ای که درجه‌ی ورودی‌اش صفر شد وارد صف می‌شود.
4. تا خالی شدن صف ادامه می‌دهیم.

```cpp linenums="1"

const int MAXN = 100000;

vector<int> adj[MAXN];
int indegree[MAXN];
vector<int> topo;

int main() {
    // خواندن گراف و پر کردن indegree

    queue<int> q;
    for (int i = 1; i <= n; i++)
        if (indegree[i] == 0)
            q.push(i);

    while (!q.empty()) {
        int v = q.front();
        q.pop();
        topo.push_back(v);

        for (int u : adj[v]) {
            indegree[u]--;
            if (indegree[u] == 0)
                q.push(u);
        }
    }

    if ((int) topo.size() != n) // (1)!
        cout << "Cycle Exists" << endl;
}
```

1. اگر همه‌ی راس‌ها وارد جواب نشده باشند، گراف دور دارد. پس الگوریتم کان هم‌زمان دور را هم تشخیص می‌دهد.

برخلاف روش DFS، این‌جا ترتیب مستقیما در `#!cpp topo` ساخته می‌شود و نیازی به برعکس کردن نیست. هر راس و هر یال یک بار پردازش می‌شود، پس زمان $O(n + m)$ است.

??? success "اثبات درستی"
    هر راس فقط وقتی وارد صف می‌شود که درجه‌ی ورودی‌اش صفر شده باشد؛ یعنی همه‌ی راس‌هایی که به آن یال دارند قبلا به جواب اضافه شده‌اند. پس برای هر یال $u \rightarrow v$، راس $u$ قبل از $v$ در جواب است و ترتیب توپولوژیک معتبر است.

    اگر گراف DAG باشد، همه‌ی راس‌ها وارد جواب می‌شوند: در غیر این صورت راس‌های باقی‌مانده همگی درجه‌ی ورودی مثبت از بین خودشان دارند و اگر از یکی از آن‌ها شروع کنیم و مدام روی یک یال ورودی به عقب برویم، چون تعدادشان متناهی است بالاخره به راسی تکراری می‌رسیم که یعنی دور داریم. پس «همه‌ی راس‌ها وارد جواب شدند» دقیقا معادل «گراف دور ندارد» است.

#### کوچک‌ترین ترتیب از نظر لغت‌نامه‌ای

یک DAG معمولا چند ترتیب توپولوژیک معتبر دارد و در سوالات زیادی از ما کوچک‌ترین آن‌ها از نظر لغت‌نامه‌ای (Lexicographically Smallest) را می‌خواهند؛ یعنی ترتیبی که راس اولش کمترین مقدار ممکن را داشته باشد، بین آن‌ها راس دومش کمترین باشد و همین‌طور تا آخر. در الگوریتم کان، هر راسی که در صف است همین الان قابل انتخاب است (همه‌ی پیش‌نیازهایش انجام شده‌اند). پس کافی است در هر مرحله به جای راس جلوی صف، **کوچک‌ترین** راس موجود را برداریم؛ یعنی صف را با یک [صف اولویت](/Level2/ds_basic/) جایگزین کنیم.

```cpp linenums="1" hl_lines="1 7"

priority_queue<int, vector<int>, greater<int>> pq; // (1)!
for (int i = 1; i <= n; i++)
    if (indegree[i] == 0)
        pq.push(i);

while (!pq.empty()) {
    int v = pq.top(); // (2)!
    pq.pop();
    topo.push_back(v);

    for (int u : adj[v]) {
        indegree[u]--;
        if (indegree[u] == 0)
            pq.push(u);
    }
}
```

1. صف اولویت پیش‌فرض بزرگ‌ترین عضو را بالا نگه می‌دارد؛ با `#!cpp greater<int>` آن را برعکس می‌کنیم تا کوچک‌ترین عضو بالا باشد.

2. تنها تفاوت با الگوریتم کان همین‌جاست: به جای `#!cpp q.front()` کوچک‌ترین راس آماده را برمی‌داریم.

??? success "چرا این انتخاب حریصانه درست است؟"
    در هر مرحله، راس‌هایی که داخل صف اولویت هستند دقیقا راس‌هایی‌اند که می‌توانند راس بعدی ترتیب باشند؛ هیچ راس دیگری نمی‌تواند بیاید چون هنوز پیش‌نیاز انجام‌نشده دارد. برای کوچک‌ترین ترتیب لغت‌نامه‌ای باید راس بعدی کمترین مقدار ممکن را داشته باشد، پس انتخاب کوچک‌ترین راس آماده اجباری است. انتخاب این راس هم هیچ راس دیگری را از ترتیب حذف نمی‌کند (گراف همچنان DAG است و بقیه بعدا وارد صف می‌شوند)، پس همین استدلال برای مراحل بعد هم تکرار می‌شود.

هر راس یک بار وارد و خارج صف اولویت می‌شود، پس زمان $O((n + m) \log n)$ است.

!!! warning ""
    «کوچک‌ترین ترتیب لغت‌نامه‌ای» با سوال «راس $1$ هر چه زودتر بیاید، بعد راس $2$ هر چه زودتر و ...» فرق دارد و این صف اولویت سوال دوم را حل نمی‌کند. برای آن سوال باید روی گراف معکوس، **بزرگ‌ترین** ترتیب لغت‌نامه‌ای را ساخت و جواب را برعکس کرد؛ این را در سوالات این بخش تمرین کنید.

### برنامه‌نویسی پویا روی DAG

یکی از مهم‌ترین کاربردهای ترتیب توپولوژیک، [دی‌پی](/Level2/dp/) روی گراف است. اگر مقدار هر راس فقط به مقدار راس‌هایی وابسته باشد که به آن یال دارند، با پردازش راس‌ها به ترتیب توپولوژیک مطمئنیم که هنگام محاسبه‌ی هر راس، همه‌ی مقادیر مورد نیاز قبلا حساب شده‌اند.

#### مسئله

یک DAG و راس مبدأ $s$ داده شده است. برای هر راس $v$ تعداد مسیرهای مختلف از $s$ به $v$ را حساب کنید.

#### راه حل

$dp[v]$ را تعداد مسیرهای $s$ به $v$ تعریف می‌کنیم. پایه $dp[s] = 1$ است (مسیر تهی). برای هر یال $u \rightarrow v$ هر مسیری که به $u$ ختم می‌شود با این یال به مسیری تا $v$ تبدیل می‌شود، پس $dp[v] \mathrel{+}= dp[u]$. فقط باید راس‌ها را به ترتیب توپولوژیک پیمایش کنیم تا وقتی از $u$ به همسایه‌هایش پخش می‌کنیم، $dp[u]$ نهایی شده باشد.

```cpp linenums="1"

vector<long long> dp(n + 1, 0);
dp[s] = 1;

for (int u : topo) // (1)!
    for (int v : adj[u])
        dp[v] += dp[u];
```

1. `#!cpp topo` همان ترتیب توپولوژیکی است که در بخش قبل ساختیم.

??? success "اثبات درستی"
    با استقرا روی ترتیب توپولوژیک: وقتی به راس $u$ می‌رسیم، همه‌ی راس‌هایی که به $u$ یال دارند قبل از آن در ترتیب بوده‌اند و سهم خود را به $dp[u]$ اضافه کرده‌اند، پس $dp[u]$ درست است. هر مسیر از $s$ به $v$ دقیقا از یکی از یال‌های ورودی $v$ می‌گذرد، پس هیچ مسیری نه از قلم می‌افتد و نه دو بار شمرده می‌شود.

هر راس و هر یال یک بار پردازش می‌شود، پس زمان $O(n + m)$ است. با همین الگو می‌توان طولانی‌ترین مسیر، کوتاه‌ترین مسیر و خیلی از مسائل دیگر روی DAG را در زمان خطی حل کرد؛ کافی است عملیات جمع را با بیشینه یا کمینه عوض کنیم.

!!! warning ""
    تعداد مسیرها می‌تواند نمایی شود؛ معمولا سوال جواب را به پیمانه‌ی عددی مانند $10^9 + 7$ می‌خواهد.
