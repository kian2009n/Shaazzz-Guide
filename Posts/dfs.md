جست‌وجوی عمق‌اول (Depth First Search) که به آن DFS می‌گوییم، الگوریتمی برای پیمایش گراف است و شاید پرکاربردترین الگوریتم گراف باشد: کد آن کوتاه است، زمان و حافظه‌ی کمی می‌گیرد و بیشتر سوالات گراف به نوعی به پیمایش نیاز دارند. در این بخش ابتدا روش‌های ذخیره‌ی گراف را می‌بینیم، سپس DFS و ویژگی‌های درخت آن را بررسی می‌کنیم و در ادامه چند مسئله‌ی کلاسیک را با آن حل می‌کنیم.

### ذخیره‌ی گراف

برای نگه داشتن یال‌های یک گراف با $n$ راس و $m$ یال سه روش رایج داریم.

#### لیست مجاورت

پرکاربردترین روش این است که برای هر راس، لیست همسایه‌هایش را در یک `#!cpp vector` نگه داریم. اگر یال‌ها وزن داشته باشند، به جای همسایه یک `#!cpp pair` از (همسایه، وزن) ذخیره می‌کنیم. حافظه‌ی این روش $O(n + m)$ است.

```cpp linenums="1"

vector<int> G[maxn]; // (1)!
vector<pair<int, int>> G2[maxn]; // (2)!

int main() {
    int n, m;
    cin >> n >> m;
    for (int i = 1; i <= m; i++) {
        int v, u, w;
        cin >> v >> u >> w;
        G[v].push_back(u); // (3)!
        G[u].push_back(v);

        G2[v].push_back({u, w});
        G2[u].push_back({v, w});
    }
}
```

1. همسایه‌های راس $v$ در `#!cpp G[v]` قرار دارند.

2. نسخه‌ی وزن‌دار: عضو اول همسایه و عضو دوم وزن یال است.

3. چون گراف بدون جهت است، یال را در لیست هر دو سر اضافه می‌کنیم.

#### ماتریس مجاورت

برای هر دو راس $v$ و $u$ در خانه‌ی `#!cpp e[v][u]` نگه می‌داریم که بین آن‌ها یال هست یا نه (یا وزن یال را). این روش $O(n^2)$ حافظه می‌گیرد و فقط برای گراف‌های کوچک مناسب است، اما بررسی وجود یال بین دو راس در آن $O(1)$ است.

#### لیست یال‌ها

گاهی فقط لازم است خود یال‌ها را داشته باشیم؛ در این صورت هر یال را به صورت یک `#!cpp pair` در یک `#!cpp vector` می‌ریزیم. این روش مثلا در الگوریتم کروسکال به کار می‌آید.

```cpp linenums="1"

vector<pair<int, int>> edges;

for (int i = 1; i <= m; i++) {
    int v, u;
    cin >> v >> u;
    edges.push_back({v, u});
}
```

### الگوریتم DFS

ابتدا راسی مانند $v$ را انتخاب می‌کنیم و آن را ریشه می‌نامیم و علامت می‌زنیم. سپس یکی از همسایه‌های علامت‌نخورده‌ی $v$ مثل $u$ را انتخاب می‌کنیم، آن را بچه‌ی $v$ می‌کنیم، علامت می‌زنیم و همین الگوریتم را از ابتدا روی $u$ اجرا می‌کنیم. هر وقت راسی به بن‌بست خورد (همه‌ی همسایه‌هایش علامت خورده بودند)، به پدرش (راسی که از آن وارد شده بودیم) برمی‌گردیم و از همان‌جا ادامه می‌دهیم. وقتی به ریشه برگشتیم و همه‌ی همسایه‌هایش علامت خورده بودند، الگوریتم تمام می‌شود.

اگر گراف همبند نباشد، DFS فقط راس‌های مولفه‌ی ریشه را می‌بیند؛ پس برای پیمایش کل گراف، الگوریتم را از هر راس علامت‌نخورده‌ای دوباره اجرا می‌کنیم.

  <figcaption>ترتیب پیمایش راس‌ها در DFS</figcaption>

DFS به تنهایی کاربرد خاصی ندارد و محاسباتی که در کنار آن انجام می‌دهیم مهم‌اند. این محاسبات دو دسته‌اند: محاسبات پیش‌ترتیب که هنگام اولین ورود به هر راس انجام می‌شوند و محاسبات پس‌ترتیب که هنگام آخرین خروج از آن.

#### درخت DFS و زیردرخت

یال‌هایی که DFS از آن‌ها عبور می‌کند (نه یال‌هایی که به راس علامت‌خورده می‌رسند و از آن‌ها رد می‌شویم) با هم یک درخت ریشه‌دار می‌سازند که به آن درخت DFS می‌گوییم. در این درخت، راس $u$ در زیردرخت $v$ است اگر و فقط اگر هر مسیر از $u$ به ریشه از $v$ بگذرد (هر راس در زیردرخت خودش هم هست). مثلا در شکل زیر راس $5$ در زیردرخت $2$ است اما راس $3$ نیست، چون مسیر مستقیم $3 - 1$ وجود دارد.

<figure markdown>
  ![dfs2](https://he-s3.s3.amazonaws.com/media/uploads/9fa1119.jpg)
  <figcaption>درخت DFS</figcaption>
</figure>

#### کد

```cpp linenums="1"

vector<int> G[maxn];
bool mark[maxn]; // (1)!

void dfs(int v) {
    mark[v] = true;
    for (int u : G[v]) {
        if (mark[u]) continue; // (2)!
        dfs(u);
    }
}
```

1. در ابتدا همه‌ی راس‌ها علامت‌نخورده‌اند و هر راس را که دیدیم علامت می‌زنیم.

2. وارد همسایه‌هایی که قبلا دیده‌ایم نمی‌شویم.

#### پیچیدگی زمانی

وارد هر راس حداکثر یک بار می‌شویم و به اندازه‌ی تعداد همسایه‌هایش هزینه می‌دهیم؛ پس هر یال از دو سرش دقیقا دو بار بررسی می‌شود و در مجموع $n + 2m$ عملیات داریم که از $O(n + m)$ است.

!!! warning ""
    عمق بازگشت DFS می‌تواند به اندازه‌ی تعداد راس‌ها شود (مثلا روی یک مسیر طولانی). در بعضی داوری‌ها پشته‌ی برنامه برای عمق $10^5$ تا $10^6$ کافی نیست و برنامه با Runtime Error می‌خوابد. در کدفورسز و بیشتر داورهای معروف این مشکل وجود ندارد، اما اگر با آن روبه‌رو شدید، باید اندازه‌ی پشته را زیاد کنید یا DFS را با یک استک دستی و بدون بازگشت بنویسید.

### مسئله‌ی مولفه‌های همبندی

گرافی با $n$ راس و $m$ یال داده شده است. تعداد مولفه‌های همبندی آن را در $O(n + m)$ پیدا کنید. (مولفه‌ی همبندی یک دسته‌ی ماکسیمال از راس‌هاست که از هر کدام به هر کدام دیگر مسیر وجود دارد.)

??? success "راه حل"
    وقتی DFS را از راس $v$ اجرا می‌کنیم، دقیقا همه‌ی راس‌های مولفه‌ی $v$ علامت می‌خورند. پس کافی است راس‌ها را به ترتیب ببینیم و هر بار که به راس علامت‌نخورده‌ای رسیدیم، از آن DFS بزنیم و یکی به تعداد مولفه‌ها اضافه کنیم.

    ```cpp linenums="1"

    int main() {
        int n, m;
        cin >> n >> m;
        for (int i = 1; i <= m; i++) {
            int v, u;
            cin >> v >> u;
            G[v].push_back(u);
            G[u].push_back(v);
        }

        int components = 0;
        for (int i = 1; i <= n; i++) {
            if (mark[i]) continue;
            dfs(i);
            components++;
        }
        cout << components << endl;
    }
    ```

### مسئله‌ی دوبخشی بودن

گرافی با $n$ راس و $m$ یال داده شده است. در $O(n + m)$ بررسی کنید که آیا گراف دوبخشی است یا نه؛ یعنی می‌توان راس‌ها را به دو دسته تقسیم کرد به طوری که هر یال بین دو دسته باشد.

??? success "راه حل"
    ابتدا یک درخت را در نظر بگیرید. دوبخشی کردن درخت یکتاست: اگر راسی را در دسته‌ی اول بگذاریم، همسایه‌هایش باید در دسته‌ی دوم باشند، همسایه‌های آن‌ها در دسته‌ی اول و همین‌طور تا آخر. پس راس‌هایی که فاصله‌ی زوج از ریشه دارند یک دسته و بقیه دسته‌ی دیگرند.

    حال برای هر مولفه‌ی گراف، درخت DFS را می‌سازیم و راس‌ها را طبق همین قاعده رنگ می‌کنیم. اگر گراف دوبخشی باشد، این تنها رنگ‌آمیزی ممکن است؛ پس کافی است هر یال غیردرختی را چک کنیم که دو سرش رنگ متفاوت داشته باشند. اگر یالی دو سر هم‌رنگ داشت، گراف دوبخشی نیست.

    ```cpp linenums="1"

    vector<int> G[maxn];
    bool mark[maxn];
    int color[maxn]; // (1)!
    bool bad = false;

    void dfs(int v) {
        mark[v] = true;
        for (int u : G[v]) {
            if (mark[u]) {
                if (color[u] == color[v]) bad = true; // (2)!
                continue;
            }
            color[u] = color[v] ^ 1; // (3)!
            dfs(u);
        }
    }

    int main() {
        int n, m;
        cin >> n >> m;
        for (int i = 1; i <= m; i++) {
            int v, u;
            cin >> v >> u;
            G[v].push_back(u);
            G[u].push_back(v);
        }
        for (int i = 1; i <= n; i++)
            if (!mark[i]) dfs(i);

        cout << (bad ? "NO" : "YES") << endl;
    }
    ```

    1. رنگ هر راس $0$ یا $1$ است و دسته‌ی آن را مشخص می‌کند.

    2. یالی با دو سر هم‌رنگ پیدا شد.

    3. دو راس مجاور باید رنگ مخالف داشته باشند.

### زمان ورود و خروج

در طول DFS به هر راس یکی از سه رنگ را می‌دهیم: در ابتدا همه‌ی راس‌ها **سفید** (دیده‌نشده) هستند. اولین باری که وارد راسی می‌شویم آن را **خاکستری** می‌کنیم؛ یعنی کارش هنوز تمام نشده و منتظر بچه‌هایش است. وقتی همه‌ی همسایه‌هایش دیده شدند و داریم به پدرش برمی‌گردیم، آن را **سیاه** می‌کنیم. در پایان همه‌ی راس‌ها سیاه‌اند.

زمان ورود (starting time) هر راس لحظه‌ای است که خاکستری می‌شود و زمان خروج (finishing time) آن لحظه‌ای است که سیاه می‌شود. اگر یک شمارنده داشته باشیم که با هر ورود و خروج یکی زیاد شود، این زمان‌ها را با `#!cpp st[v]` و `#!cpp en[v]` نشان می‌دهیم.

```cpp linenums="1"

vector<int> G[maxn];
bool mark[maxn];
int timer = 0, st[maxn], en[maxn];

void dfs(int v) {
    st[v] = ++timer; // (1)!
    mark[v] = true;
    for (int u : G[v]) {
        if (mark[u]) continue;
        dfs(u);
    }
    en[v] = ++timer; // (2)!
}
```

1. محاسبه‌ی پیش‌ترتیب: زمان ورود.

2. محاسبه‌ی پس‌ترتیب: زمان خروج.

سه لم مهم درباره‌ی این زمان‌ها داریم:

1. $st[v] < st[u]$ اگر و فقط اگر $v$ جد $u$ باشد، یا $v$ قبل از ورود به $u$ سیاه شده باشد.
2. $en[v] < en[u]$ اگر و فقط اگر $u$ جد $v$ باشد، یا $v$ قبل از ورود به $u$ سیاه شده باشد.
3. اگر $st[v] < st[u]$ و $en[u] < en[v]$ باشد، آنگاه $v$ جد $u$ است.

??? success "اثبات لم ۳"
    دو لم اول مستقیم از نحوه‌ی کار DFS نتیجه می‌شوند. برای لم سوم فرض کنید $v$ جد $u$ نباشد. طبق لم ۱ یعنی $v$ قبل از ورود به $u$ سیاه شده و طبق لم ۲ یعنی $u$ قبل از ورود به $v$ سیاه شده است؛ این دو نمی‌توانند هم‌زمان درست باشند. پس $v$ جد $u$ است.

!!! danger "مهم"
    در تمام مدتی که راس $v$ خاکستری است، DFS در زیردرخت $v$ قرار دارد. به بیان دیگر، بازه‌ی $[st[v], en[v]]$ دقیقا شامل بازه‌های زمانی راس‌های زیردرخت $v$ است و بازه‌های دو راس یا تودرتو هستند یا کاملا جدا.

نتیجه‌ی مهم این ویژگی این است که وقتی از راسی خارج می‌شویم، کار کل زیردرخت آن تمام شده است؛ پس می‌توانیم جواب هر راس را از روی جواب بچه‌هایش حساب کنیم. به همین دلیل معمولا [دی‌پی](/Level2/dp/) روی درخت را با DFS پیاده می‌کنند.

#### مسئله: آیا $v$ جد $u$ است؟

درختی با $n$ راس و $q$ پرسش داده شده است. در هر پرسش باید بگوییم آیا راس $v$ جد راس $u$ است یا نه. الگوریتمی از $O(n + q)$ می‌خواهیم.

??? success "راه حل"
    طبق نکته‌ی بالا، $v$ جد $u$ است اگر و فقط اگر بازه‌ی زمانی $u$ داخل بازه‌ی زمانی $v$ باشد:

    $$st[v] \leq st[u] \quad \text{و} \quad en[u] \leq en[v]$$

    ```cpp linenums="1"

    bool isAncestor(int v, int u) {
        return st[v] <= st[u] && en[u] <= en[v];
    }
    ```

    یک DFS برای محاسبه‌ی زمان‌ها $O(n)$ و هر پرسش $O(1)$ است؛ در مجموع $O(n + q)$.

#### مسئله: $k$امین جد

درختی با $n$ راس و $q$ پرسش داده شده است. در هر پرسش باید $k$امین جد راس $v$ را پیدا کنیم. الگوریتمی از $O(n + q \log n)$ می‌خواهیم.

??? success "راه حل"
    اگر ارتفاع راس $v$ را $h[v]$ بنامیم، جواب راسی در ارتفاع $h[v] - k$ است که جد $v$ باشد. طبق لم‌های بالا، در بین راس‌های ارتفاع $h[v] - k$، جد $v$ دقیقا راسی است که بزرگ‌ترین زمان ورود کوچک‌تر یا مساوی $st[v]$ را دارد.

    پس برای هر ارتفاع، یک `#!cpp vector` از راس‌های آن ارتفاع می‌سازیم که بر حسب زمان ورود مرتب‌اند (اگر راس‌ها را به ترتیب ورود اضافه کنیم خودبه‌خود مرتب‌اند). این کار $O(n)$ است و هر پرسش به یک [باینری سرچ](/Level1/binary_search/) روی یکی از این وکتورها تبدیل می‌شود.

### انواع یال

درخت DFS شامل یال‌هایی است که الگوریتم از آن‌ها عبور کرده و پدر هر راس، راسی است که از آن وارد شده‌ایم. بقیه‌ی یال‌های گراف در درخت نیستند. به طور کلی یال‌های گراف چهار دسته‌اند:

1. یال درختی (Tree Edge): یال‌های درخت DFS.
2. یال عقب‌رو (Back Edge): از یک راس به یکی از جدهایش.
3. یال جلورو (Forward Edge): از یک راس به راسی در زیردرختش.
4. یال میانی (Cross Edge): هیچ‌کدام از سه حالت بالا.

در گراف بدون جهت، دسته‌ی دوم و سوم یکی هستند؛ چون یال جهت ندارد و هر یال جلورو از طرف دیگر یک یال عقب‌رو است.

  ![dfs3](https://opedia.ir/_media/learn/algorithms/270px-tree_edges.svg.png?w=300&tok=d0da4b)
  <figcaption>انواع یال نسبت به درخت DFS</figcaption>
</figure>

!!! danger "لم مهم"
    در درخت DFS یک گراف **بدون جهت**، یال میانی وجود ندارد؛ یعنی هر یال غیردرختی بین یک راس و یکی از جدهایش است.

??? success "اثبات"
    فرض کنید یال $(v, u)$ یال میانی باشد و $v$ زودتر خاکستری شده باشد. تا قبل از سیاه شدن $v$ همه‌ی همسایه‌هایش بررسی می‌شوند؛ پس $u$ (که همسایه‌ی $v$ است) در بازه‌ی خاکستری بودن $v$ خاکستری می‌شود. طبق نکته‌ی قبل، در این بازه داخل زیردرخت $v$ هستیم، پس $u$ در زیردرخت $v$ است و این یال عقب‌رو است نه میانی.

این لم در بسیاری از سوالات (مثل یال برشی و راس برشی در ادامه) به کار می‌آید.

#### مسئله: تشخیص دور در گراف بدون جهت

آیا گراف بدون جهت داده‌شده دور دارد؟ با لم بالا جواب ساده می‌شود: اگر گراف دور داشته باشد، حداقل یکی از یال‌های دور در درخت DFS نیست (چون درخت دور ندارد) و طبق لم این یال، یک یال عقب‌رو است؛ یعنی هنگام DFS از راس $v$ به همسایه‌ای می‌رسیم که **قبلا دیده شده** و **پدر $v$ نیست**. برعکس، هر یال عقب‌رو با مسیر درختی بین دو سرش یک دور می‌سازد. پس گراف دور دارد اگر و تنها اگر در DFS به چنین یالی برسیم.

```cpp linenums="1"

vector<int> adj[MAXN];
bool visited[MAXN];

bool dfs(int v, int par) { // (1)!
    visited[v] = true;
    for (int u : adj[v]) {
        if (u == par) continue; // (2)!
        if (visited[u]) return true; // (3)!
        if (dfs(u, v)) return true;
    }
    return false;
}

bool has_cycle(int n) {
    for (int v = 1; v <= n; v++)
        if (!visited[v] && dfs(v, -1))
            return true;
    return false;
}
```

1. پدر $v$ را هم به تابع می‌دهیم تا یال درختی‌ای که از آن آمده‌ایم را با یال عقب‌رو اشتباه نگیریم.

2. یال به پدر همان یالی است که از آن وارد $v$ شده‌ایم؛ این یال دور نمی‌سازد.

3. به راسی رسیده‌ایم که قبلا دیده شده و پدر ما نیست؛ طبق لم این یال عقب‌رو است و با مسیر درختی تا $u$ یک دور بسته می‌شود.

چون این همان DFS معمولی است، زمان $O(n + m)$ است. برای گراف‌های ناهمبند باید از هر راس دیده‌نشده دوباره DFS بزنیم تا همه‌ی مولفه‌ها بررسی شوند.

!!! warning ""
    اگر گراف یال چندگانه داشته باشد (دو یال بین یک جفت راس)، این دو یال خودشان یک دور می‌سازند، اما کد بالا با شرط `#!cpp u == par` هر دو را رد می‌کند. در این حالت باید به جای «راس پدر»، **شماره‌ی یالی** که از آن آمده‌ایم را نگه داریم و فقط همان یک یال را رد کنیم.

!!! tip "نکته"
    در درخت DFS یک گراف **جهت‌دار** یال میانی هم وجود دارد و این استدلال کار نمی‌کند؛ تشخیص دور در گراف جهت‌دار را با رنگ‌آمیزی سه‌رنگی در [مرتب‌سازی توپولوژیک](/Level2/topol_sort/) می‌بینیم.

### قطر درخت

بلندترین مسیر درخت را قطر می‌گوییم (فاصله‌ی دو راس یعنی تعداد یال‌های مسیر بین آن‌ها). می‌خواهیم طول قطر و دو سر آن را در $O(n)$ پیدا کنیم.

??? success "راه حل"
    از یک راس دلخواه DFS می‌زنیم و دورترین راس از آن را $a$ می‌نامیم. سپس از $a$ دوباره DFS می‌زنیم و دورترین راس از $a$ را $b$ می‌نامیم. مسیر $a$ تا $b$ یک قطر است. دو DFS داریم، پس زمان $O(n)$ است. اثبات این روش و یک راه حل دیگر با دی‌پی روی درخت را می‌توانید در [کتاب گراف شاززز](https://gtoi.shaazzz.ir/book/2/6.html) بخوانید.

### یال برشی و راس برشی

**یال برشی** یالی است که با حذف آن تعداد مولفه‌های همبندی گراف زیاد شود و **راس برشی** راسی است که با حذف آن (و یال‌هایش) تعداد مولفه‌ها زیاد شود.

#### مسئله: پیدا کردن یال‌های برشی

گرافی با $n$ راس و $m$ یال داده شده است (ممکن است یال چندگانه داشته باشد). همه‌ی یال‌های برشی را در $O(n + m)$ پیدا کنید.

??? success "راه حل"
    از درخت DFS کمک می‌گیریم. اول این که هیچ یال غیردرختی برشی نیست، چون با حذف آن درخت DFS سر جایش می‌ماند و گراف همبند است. پس فقط باید یال‌های درختی را بررسی کنیم.

    اگر یال درختی بین $v$ و پدرش را حذف کنیم، درخت به دو قسمت «زیردرخت $v$» و «بقیه» تقسیم می‌شود و این یال برشی است اگر و فقط اگر هیچ یال غیردرختی این دو قسمت را به هم وصل نکند. طبق لم بخش قبل، هر یال غیردرختی که یک سرش داخل زیردرخت $v$ است، یا هر دو سرش داخل زیردرخت است یا سر دیگرش یکی از جدهای $v$ است.

    ارتفاع هر راس را $dis[v]$ و کمترین ارتفاعی که از زیردرخت $v$ با یک یال غیردرختی می‌توان به آن رسید را $d[v]$ بنامید. آنگاه یال $v$ به پدرش برشی است اگر و فقط اگر $d[v] \geq dis[v]$؛ چون در غیر این صورت یالی از زیردرخت $v$ به جدی بالاتر از $v$ وجود دارد که دو قسمت را به هم وصل می‌کند.

    محاسبه‌ی $d[v]$ ساده است: کمینه‌ی $dis[u]$ برای یال‌های غیردرختی $(v, u)$ و $d[u]$ برای بچه‌های $u$ (هر یال یا به خود $v$ وصل است یا داخل زیردرخت یکی از بچه‌هاست). فقط باید یال به پدر را در $d[v]$ حساب نکنیم؛ اما چون ممکن است چند یال موازی بین $v$ و پدرش باشد، فقط **اولین** یال به پدر را نادیده می‌گیریم.

    ```cpp linenums="1"

    vector<int> G[maxn];
    bool mark[maxn];
    int dis[maxn], d[maxn];

    void dfs(int v, int p) { // (1)!
        mark[v] = true;
        bool skipped = false; // (2)!
        d[v] = dis[v];
        for (int u : G[v]) {
            if (mark[u]) {
                if (u == p && !skipped) {
                    skipped = true;
                    continue;
                }
                d[v] = min(d[v], dis[u]);
                continue;
            }
            dis[u] = dis[v] + 1;
            dfs(u, v);
            d[v] = min(d[v], d[u]);
        }
        if (p != -1 && d[v] >= dis[v]) // (3)!
            cout << p << ' ' << v << endl;
    }

    int main() {
        int n, m;
        cin >> n >> m;
        for (int i = 1; i <= m; i++) {
            int v, u;
            cin >> v >> u;
            G[v].push_back(u);
            G[u].push_back(v);
        }
        for (int i = 1; i <= n; i++)
            if (!mark[i]) dfs(i, -1);
    }
    ```

    1. $p$ پدر $v$ در درخت DFS است و برای ریشه $-1$ می‌گذاریم.

    2. فقط اولین یال به پدر را نادیده می‌گیریم تا یال‌های موازی درست حساب شوند.

    3. هیچ یالی از زیردرخت $v$ به بالاتر از $v$ نمی‌رود، پس یال $(p, v)$ برشی است.

#### مسئله: پیدا کردن راس‌های برشی

همان گراف داده شده است. همه‌ی راس‌های برشی را در $O(n + m)$ پیدا کنید.

??? success "راه حل"
    مانند قبل DFS می‌زنیم و $dis[v]$ و $d[v]$ را حساب می‌کنیم. ریشه حالت خاصی است: ریشه برشی است اگر و فقط اگر در درخت DFS بیش از یک بچه داشته باشد؛ چون طبق لم، بین زیردرخت بچه‌های مختلف ریشه هیچ یالی نیست و با حذف ریشه هر زیردرخت یک مولفه‌ی جدا می‌شود، در حالی که با یک بچه، بقیه‌ی گراف همبند می‌ماند.

    برای راس غیر ریشه‌ی $v$، بعد از حذف آن قسمت‌های «زیردرخت هر بچه‌ی $u$» و «بقیه‌ی گراف» جدا می‌شوند و باز هم بین زیردرخت بچه‌های مختلف یالی نیست. پس هر زیردرخت $u$ فقط می‌تواند از طریق یالی به جدهای $v$ به بقیه وصل بماند. در نتیجه $v$ برشی است اگر و فقط اگر بچه‌ای مانند $u$ داشته باشد که $d[u] \geq dis[v]$ باشد.

    ```cpp linenums="1"

    vector<int> G[maxn];
    bool mark[maxn];
    int dis[maxn], d[maxn];

    void dfs(int v, int p) {
        mark[v] = true;
        int children = 0;
        bool cut = false;
        d[v] = dis[v];
        for (int u : G[v]) {
            if (mark[u]) {
                d[v] = min(d[v], dis[u]); // (1)!
                continue;
            }
            dis[u] = dis[v] + 1;
            dfs(u, v);
            d[v] = min(d[v], d[u]);
            if (d[u] >= dis[v]) cut = true; // (2)!
            children++;
        }
        if (p == -1 && children > 1) cout << v << ' '; // (3)!
        if (p != -1 && cut) cout << v << ' ';
    }
    ```

    1. این‌جا لازم نیست یال به پدر را نادیده بگیریم؛ چون شرط $d[u] \geq dis[v]$ است و یال $u$ به $v$ مقدار $d[u]$ را فقط تا $dis[v]$ پایین می‌آورد که شرط را تغییر نمی‌دهد.

    2. زیردرخت $u$ هیچ یالی به بالاتر از $v$ ندارد و با حذف $v$ جدا می‌شود.

    3. حالت ریشه: بیش از یک بچه در درخت DFS.

### مرکز درخت

مرکز (Center) درخت راسی است که بیشترین فاصله‌اش از بقیه‌ی راس‌ها کمینه باشد. هر درخت یک یا دو مرکز دارد.

??? success "راه حل"
    مرکز درخت دقیقا راس وسط قطر است: اگر طول قطر زوج باشد یک مرکز و اگر فرد باشد دو مرکز (دو راس وسط) داریم. پس قطر و مسیر آن را مانند بخش قبل در $O(n)$ پیدا می‌کنیم و راس یا راس‌های وسط آن را خروجی می‌دهیم.

!!! warning ""
    مرکز درخت ربطی به میانگین یا مرکز هندسی ندارد؛ فقط بر اساس فاصله‌ها تعریف می‌شود.

### سنتروید درخت

سنتروید (Centroid) درخت راسی است که با حذف آن، اندازه‌ی هر مولفه‌ی باقی‌مانده حداکثر $\frac{n}{2}$ باشد. هر درخت یک یا دو سنتروید دارد.

??? success "راه حل"
    درخت را از راس $1$ ریشه‌دار می‌کنیم و با یک DFS اندازه‌ی زیردرخت هر راس یعنی $sz[v]$ را حساب می‌کنیم. با حذف $v$ دو نوع مولفه به وجود می‌آید: زیردرخت هر بچه‌ی $u$ به اندازه‌ی $sz[u]$ و قسمت بالایی شامل پدر به اندازه‌ی $n - sz[v]$. پس $v$ سنتروید است اگر و فقط اگر برای همه‌ی بچه‌ها $sz[u] \leq \frac{n}{2}$ و همچنین $n - sz[v] \leq \frac{n}{2}$ باشد.

    ```cpp linenums="1"

    vector<int> G[maxn];
    int sz[maxn];

    void dfs(int v, int p) {
        sz[v] = 1;
        for (int u : G[v]) {
            if (u == p) continue;
            dfs(u, v);
            sz[v] += sz[u];
        }
    }

    int main() {
        int n;
        cin >> n;
        for (int i = 1; i < n; i++) {
            int v, u;
            cin >> v >> u;
            G[v].push_back(u);
            G[u].push_back(v);
        }

        dfs(1, -1);

        for (int v = 1; v <= n; v++) {
            bool ok = (n - sz[v] <= n / 2);
            for (int u : G[v])
                if (sz[u] < sz[v] && sz[u] > n / 2) // (1)!
                    ok = false;
            if (ok) cout << v << ' ';
        }
    }
    ```

    1. همسایه‌ای که زیردرخت کوچک‌تری دارد، بچه‌ی $v$ است (پدر همیشه زیردرخت بزرگ‌تری دارد).

    محاسبه‌ی اندازه‌ها یک DFS است و در حلقه‌ی پایانی هر یال تعداد ثابتی بار بررسی می‌شود؛ پس زمان کل $O(n)$ است.

!!! tip "نکته"
    مرکز بر اساس فاصله‌ها و سنتروید بر اساس اندازه‌ی مولفه‌ها بعد از حذف راس تعریف می‌شود؛ این دو را با هم اشتباه نگیرید. سنتروید پایه‌ی تکنیک مهمی به نام تجزیه‌ی سنتروید است که در سطوح بعدی می‌بینید.
